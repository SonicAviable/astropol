# WargameRTS — техническое задание

Версия: 1.0 · Статус: утверждено к разработке · Приоритет: **одиночная кампания**

Документ расширяет `docs/GAME_DESIGN.md` (механики и вехи) и задаёт конкретные
требования, поведение, данные и критерии приёмки. Если документы расходятся —
приоритет у этого ТЗ.

---

## 1. Видение

Тактическая RTS в реальном времени в духе Wargame: Red Dragon. Игрок собирает
колоду современной техники, тратит очки командования на подкрепления и ведёт
войска по большим картам, захватывая сектора. Главный режим — **одиночная
кампания**: последовательность миссий, где выжившие подразделения переходят из
боя в бой и получают опыт.

Рамки оригинала:
- механики, структура матча, масштаб боя и роль секторов — по духу оригинала;
- **не копируем:** ассеты, модели, звуки, музыку, тексты, логотипы, названия
  фракций и юнитов, оформление интерфейса 1:1;
- все названия миссий, юнитов и фракций — оригинальные (см. раздел 5).

## 2. Платформа и технологии

| Параметр | Требование |
|---|---|
| Движок | Unity 6000.6.3f1, URP |
| Ввод | Input System (Active Input Handling = Both) |
| Язык | C# 9, .NET Standard 2.1 |
| Целевая платформа | Windows PC (основная), macOS и Linux — по возможности |
| Разрешение | 1920×1080 и 2560×1440 (основные), 16:9 и 16:10 |
| Интерфейс | IMGUI на этапе прототипа; переход на UI Toolkit — отдельная веха |
| Сохранения | JSON в `Application.persistentDataPath` |

## 3. Режимы игры

| Режим | Статус | Описание |
|---|---|---|
| **Одиночная кампания** | **Приоритет 1** | Серия миссий, выжившие переходят дальше, сохранение прогресса |
| Бой с ИИ | Готов (базовый) | Одиночная быстрая партия, две армии, победа по уничтожению |
| Песочница | Готов | Спавн любой техники, управление временем, читы; для тестов |
| Мультиплеер | Отложен | Решение (lockstep или сервер) — после завершения кампании |

## 4. Игровой цикл миссии

Миссия состоит из четырёх фаз:

1. **Брифинг** — текст задачи, карта, цели, состав сил, награда (кампания).
2. **Развёртывание** — стартовые юниты уже стоят в зоне развёртывания; игрок
   может переставить их внутри зоны за 60 секунд (v2 — в v1 не реализуется,
   см. раздел 21).
3. **Бой** — реальное время, игрок отдаёт приказы, покупает подкрепления,
   захватывает сектора. Пауза и изменение скорости времени доступны (кроме
   сетевой игры).
4. **Итог** — победа или поражение, статистика, список выживших, переход к
   следующей миссии или повтор.

Таймер матча показывает прошедшее время. Для миссий с лимитом времени
показывается обратный отсчёт.

## 5. Кампания

### 5.1. Структура

- Кампания — **линейная последовательность из 8 миссий** (ветвление —
  в версии 2).
- Сюжет — вымышленный регион «Долина Кестрел» и приграничный конфликт двух
  блоков: **Синие** (силы коалиции, игрок) и **Красные** (противник).
- Каждая миссия имеет: идентификатор, название, брифинг (2–4 предложения),
  уровень сложности (1–3), тип цели, размер карты, состав сил, пул подкреплений
  и награду.

### 5.2. Список миссий (v1)

| № | Название | Тип цели | Карта | Секторов | Сложность |
|---|---|---|---|---|---|
| 1 | Первый рубеж | Захват секторов: все сектора | 1.5 км | 3 | 1 |
| 2 | Переправа | Удержание: 8 мин, нужно ≥2 сектора | 2 км | 4 | 1 |
| 3 | Лесной коридор | Захват: все сектора | 2.5 км | 4 | 2 |
| 4 | Велен | Захват: все сектора (на городах) | 2.5 км | 5 | 2 |
| 5 | Контрудар | Удержание: 10 мин, нужно ≥3 сектора | 2.5 км | 5 | 2 |
| 6 | Артиллерийский парк | Уничтожение противника | 2.5 км | 3 | 2 |
| 7 | Ночные колонны | Уничтожение противника | 3 км | 4 | 3 |
| 8 | Последний рубеж | Захват: все сектора | 3 км | 6 | 3 |

Таблица — стартовая; баланс проверяется playtest-ом (раздел 18).

### 5.3. Типы целей

- **Захват (CaptureAll):** победа, когда Синие владеют всеми секторами.
- **Удержание (Hold):** по истечении времени Синие должны владеть не меньше
  `RequiredSectors`. Раньше времени победа не засчитывается.
- **Уничтожение (Eliminate):** победа, когда у Красных нет живых юнитов **и**
  нет очков командования хотя бы на самый дешёвый юнит из их пула.

### 5.4. Поражение (во всех миссиях)

- У Синих нет живых юнитов **и** нет очков командования на самый дешёвый юнит;
- для Hold — истёк таймер и секторов меньше требуемого.

### 5.5. Выжившие и прогресс

- При **победе** записываются все живые юниты Синих: тип, уровень опыта,
  доля здоровья. Опыт +1 за миссию (максимум 2 уровня).
- Выжившие переходят в следующую миссию и ставятся в тыловой строй
  (сверх базовых сил миссии, лимит 40 юнитов).
- При **поражении** прогресс не меняется, выжившие предыдущей победы сохраняются.
- Кампанию можно прервать в любой момент; прогресс сохраняется после каждой
  миссии (не внутри миссии).
- «Новая кампания» — с подтверждением (два нажатия).

### 5.6. Экран кампании

- Карта с 8 узлами, соединёнными линией. Состояния узла: **пройдено** (галочка),
  **текущая** (подсветка), **закрыта** (серый).
- Панель выбранной миссии: название, брифинг, цель, сложность (звёзды),
  размер карты, число выживших, кнопка «Начать» (доступна только текущей миссии).
- Кнопки: «Начать миссию», «Новая кампания», «Назад».

## 6. Экономика

### 6.1. Очки командования (CP)

- Синие получают стартовые CP (по миссии: 200–350).
- Доход: **сектора × доход за сектор в секунду** (по миссии: 1.0–1.5 CP/с
  у игрока). Нейтральные и спорные сектора дохода не дают.
- Противник получает CP по той же схеме; множитель сложности 0.9 / 1.0 / 1.2.
- Потраченные CP не возвращаются.

### 6.2. Подкрепления

- Игрок покупает юнит кликом по карточке в панели подкреплений. Юнит появляется
  в тыловой зоне своей стороны (точка сброса — центр зоны развёртывания).
- Цена — `UnitDefinition.Cost`. Покупка невозможна при нехватке CP или при
  достигнутом лимите юнитов (`UnitCap`, по умолчанию 60 на сторону).
- Пул подкреплений задаётся миссией (6–9 типов). Пул игрока и пул противника
  могут различаться.
- ИИ покупает каждые 4 секунды (делённые на множитель сложности) один юнит
  из своего пула, если хватает CP и не достигнут лимит.

### 6.3. Панель подкреплений (HUD)

- Нижняя центральная часть экрана; слева — миникарта, справа — панель приказов.
- Показывает: текущие CP, доход в секунду, карточки пула.
- Карточка: иконка типа, название, цена, подсказка при наведении (броня,
  скорость, оружие, дальность).
- Карточка неактивна, если не хватает CP или достигнут лимит.

## 7. Сектора

- Сектор — круглая зона радиусом **80 м** (по умолчанию) с центром на земле.
- Контроль: значение `Control` от −1 (полностью Красные) до +1 (полностью Синие).
- Прогресс за секунду: `0.1 × min(число своих юнитов в зоне, 5)`. Если в зоне
  есть юниты обеих сторон — прогресса нет. Если в зоне никого нет — значение
  медленно (0.02/с) возвращается к нулю.
- **Владелец:** сторона, у которой `Control ≥ 0.5` (Синие) или `≤ −0.5` (Красные).
  Между −0.5 и 0.5 владельца нет (сектор спорный).
- Размещение: сначала на городах (по порядку), затем случайные точки в центральной
  полосе карты (|z| ≤ 0.3·размер карты), минимальное расстояние между секторами
  380 м. Раскладка детерминирована по seed миссии.
- Визуал: кольцо на земле (цвет по владельцу, нейтральный — белый), столб-флаг.
  На миникарте — маркер сектора с цветом владельца.

## 8. Боевая система

### 8.1. Видимость и разведка

- Линия видимости учитывает рельеф, здания (препятствия) и глубину леса
  (больше 60 м леса — блок).
- Дальность обнаружения = `OpticsRange × Concealment` цели. Лес ×0.5, город для
  пехоты ×0.6, движение ×1.25, недавний выстрел — не ниже 0.9.
- **v1:** только текущая видимость (без «последней известной позиции»).
  **v2:** маркер последней известной позиции (см. раздел 21).

### 8.2. Точность

- Базовая точность — `WeaponDefinition.Accuracy`.
- Множители: движение стрелка (`MovingAccuracyMultiplier`), укрытие цели (×0.6),
  дистанция (линейно до ×0.6 на максимальной дальности).
- **Ветеранство (v1):** ×(1 + 0.1 × уровень), уровни 0–2.

### 8.3. Бронирование и урон

- Броня по зонам: лоб (≤45° от направления), борт (45–135°), корма (≥135°).
- Бронебойный урон: если пробитие > броня — `1 + (пробитие − броня) × 0.5`;
  при броне 0 — 1. Фугасный урон: `HE / (1 + броня)`.
- Укрытие пехоты в лесу и городе: урон ×0.5.
- Урон сплэш-снарядов: линейно убывает от центра до края радиуса.

### 8.4. Здоровье и смерть

- Здоровье = `MaxHealth`; при 0 юнит погибает, остаётся обломок 60 с.
- Выжившие в кампании переносят долю здоровья (см. 5.5).

### 8.5. Артиллерия (v1)

- Непрямой огонь (САУ, РСЗО) по целям, которые видит команда, без своей
  линии видимости.
- Залп РСЗО — 12 снарядов с интервалом 0.18 с.
- Минимальная дальность — 400–500 м.
- Снаряд летит `1.5 с + дистанция / 450 м/с`; рассеивание пропорционально
  дистанции.

### 8.6. Подавление и мораль (v2 — веха C6)

Описано для будущей реализации: огонь копит подавление; состояния «подавлен»
(хуже точность), «прижат» (не движется, стреляет), «бегство» (выход из боя);
восстановление со временем. В v1 не реализуется.

### 8.7. Авиация, ПВО, дым, снабжение, транспорт (v2 — вехи C7–C8)

Описано для будущей реализации. В v1 отсутствуют; соответствующие кнопки
панели приказов неактивны.

## 10. Искусственный интеллект

### 10.1. Уровни сложности

| Уровень | Множитель дохода | Интервал покупки | Волны атак |
|---|---|---|---|
| Лёгкий | 0.9 | 5 с | редко |
| Средний | 1.0 | 4 с | обычно |
| Сложный | 1.2 | 3 с | часто |

Сложность выбирается в настройках кампании (по умолчанию средний). Миссии
задают свою базовую сложность, которая меняет состав сил противника.

### 10.2. Поведение (v1)

- **Стратегия:** выбор ближайшего сектора, не занятого Красными; отправка
  простаивающих юнитов волнами (группы 3–6) в режиме атаки движением.
- **Покупка:** случайный юнит из пула, пока хватает CP и не достигнут лимит.
- **Тактика:** атакует видимых врагов в дальности; отступление — не в v1.

### 10.3. Поведение (v2)

Укрытие, фланги, отход раненых, артиллерийская поддержка по обнаруженным
целям, перераспределение сил по захваченным секторам.

## 11. Управление

| Действие | Клавиши / мышь |
|---|---|
| Камера | WASD / стрелки / край экрана (вкл/выкл) |
| Зум | колесо |
| Поворот | Q/E или средняя кнопка мыши |
| Выделение | ЛКМ, рамка ЛКМ, Shift — добавить, двойной клик — все такого типа на экране |
| Группы | Ctrl+1..9 — назначить, 1..9 — выбрать, дважды — камера к группе |
| Движение | ПКМ по земле — строем; ПКМ с протяжкой — линия; ПКМ по миникарте |
| Атака | ПКМ по видимому врагу; Ctrl+ПКМ — движение с атакой |
| Стоп | X |
| Отход | B |
| Режим огня | H (по кругу: по готовности → только ответный → не стрелять) |
| Туман войны (в бою) | F |
| Подсказка | F1 |
| Пауза / меню | Esc (если ничего не выделено) или F10 |
| Подкрепления | ЛКМ по карточке (покупка); Shift — не закрывает режим |

Мышь и клавиатура — единственный способ ввода в v1; геймпад — v2.

## 12. Интерфейс

### 12.1. Экраны

1. **Главное меню:** Кампания, Бой с ИИ, Песочница, Настройки, Выход.
2. **Кампания:** карта миссий, панель выбранной миссии (раздел 5.6).
3. **Брифинг:** перед стартом миссии — текст, карта-превью, цель, состав сил.
   В v1 брифинг объединён с панелью выбора миссии.
4. **Бой:** HUD (раздел 12.2).
5. **Пауза:** продолжить, настройки, перезапуск миссии, главное меню, выход.
6. **Итог миссии:** победа/поражение, время, секторы в конце, потери, выжившие,
   кнопки «К кампании», «Повторить», «Главное меню».
7. **Настройки:** масштаб UI, качество, скорость камеры, прокрутка краем, VSync,
   полный экран, громкость (v1 — заглушки).

### 12.2. HUD боя

- **Верх по центру:** счёт юнитов сторон, полоски сил, таймер, режим/время.
- **Верх справа:** CP (в кампании) и доход.
- **Слева внизу:** миникарта (ландшафт, юниты, сектора, обзор камеры).
- **Внизу по центру:** панель подкреплений (кампания) или инструменты песочницы.
- **Справа внизу:** панель приказов 4×3 и панель выбранных юнитов.
- **Над юнитами:** значок НАТО в рамке цвета стороны, полоска здоровья, рамка
  выделения.
- **Над землёй:** кольца секторов с владельцем.

Макет — `docs/ui-reference/hud-mockup.jpg`.

### 12.3. Подсказки и тултипы

- Тултип при наведении на кнопку, карточку и юнит.
- Подсказка текущего приказа у курсора.

## 13. Аудио (заглушки в v1)

- Музыка: меню, бой (спокойная / напряжённая), итог победы и поражения.
- SFX: выстрел по типу оружия, попадание, взрыв, покупка подкрепления,
  захват сектора (начало и окончание), предупреждение «сектор теряется».
- В v1 — таблица событий и точки вызова (`AudioEvents`), звуки — заглушки
  без ассетов.

## 14. Графика

- Стилизованный реализм (как в текущем прототипе): низкополигональные
  заглушки, реальные текстуры позже.
- Ландшафт: рельеф по шуму Перлина, текстура по высоте и типу местности
  (лес, город, зона развёртывания).
- Леса: кластеры конусов, городские блоки: кубы-заглушки.
- Туман дальности, тени, URP.
- Визуальная обратная связь: трассеры, вспышки, взрывы, кольца секторов.

## 15. Производительность

| Параметр | Цель |
|---|---|
| Юниты на сцене | до 300 (120 на сторону + обломки) |
| Кадр | 60 FPS на RTX 3060 при 1440p |
| Время загрузки миссии | до 5 с на 3 км карте (без учёта NavMesh bake) |
| Пауза в симуляции | не более 4 мс на кадр в среднем |
| Видимость | обновление раз в 0.25 с, пакетная проверка |

При превышении бюджета — приоритет: уменьшение частоты обновлений видимости и
ИИ, затем LOD моделей.

## 16. Сохранения и настройки

- Прогресс кампании: `campaign.json` в `persistentDataPath`. Формат:
  версия, индекс текущей миссии, список пройденных, список выживших.
- Настройки: `PlayerPrefs` (ключи с префиксом `WargameRTS.`).
- Ошибки чтения/записи — не падают, пишут предупреждение, при необходимости
  начинают новую кампанию с подтверждением.
- Сохранение внутри миссии в v1 не поддерживается.

## 17. Архитектура кода

Пространства имён: `WargameRTS.<Папка>`. Сборка — `WargameRTS.Runtime`,
редактор — `WargameRTS.Editor`, тесты — `WargameRTS.Tests`.

```
Core/        — загрузчики сцен, MatchSettings, BattleRules, InputGate, настройки,
               CampaignManager, MissionObjectiveSystem, EconomySystem
Campaign/    — CampaignCatalog (миссии), MissionDefinition, CampaignSave,
               SurvivorRecord
Map/         — GameMap, SectorSystem, Sector
Units/       — Unit, UnitView, UnitFactory, UnitCatalog, UnitDefinition
Combat/      — CombatMath, LineOfSight, ShellManager, VisibilitySystem,
               WeaponDefinition
Selection/   — SelectionManager, CommandInput, FormationPlanner
CameraRig/   — RtsCameraController
AI/          — SimpleEnemyAI
UI/          — BattleHud, MainMenu, PauseMenu, SettingsPanel, HudStyle, HudIcons,
               MinimapView, ReinforcementBar
Sandbox/     — SandboxController
Editor/      — меню и открытие сцен, импорт UI-текстур
```

Принципы:
- Симуляция и представление разделены: юниты не знают о UI, UI читает состояние
  через статические точки доступа (`Unit.All`, `SectorSystem.Instance`,
  `EconomySystem.Instance`).
- Миссии описаны данными (`MissionDefinition`), а не отдельными сценами.
  Все миссии работают в сцене `Battle`.
- Общие переключатели текущего боя — в `BattleRules`, параметры миссии — в
  `MatchSettings`/`MissionDefinition`.
- Ввод разруливается `InputGate`.

## 18. Тестирование и приёмка

### 18.1. Автоматические проверки

- `Tools/CompileCheck/check.sh` — компиляция против UnityEngine reference
  assemblies (обязательна перед каждым коммитом).
- EditMode-тесты (WargameRTS.Tests, веха C2+):
  - формула урона (пробитие, фугас, укрытие);
  - формула контроля сектора (прогресс, владелец, спорность);
  - экономика (доход, покупка, лимит);
  - сохранение и загрузка CampaignSave (round-trip JSON);
  - выбор выживших (лимит 40, повышение опыта до 2).

### 18.2. Чек-лист playtest (ручной, в Unity)

Для каждой миссии кампании:
1. Миссия стартует без ошибок в консоли.
2. Цель отображается, таймер и сектора видны.
3. Сектора меняют владельца, доход CP растёт.
4. Покупка подкреплений работает, лимит соблюдается.
5. Победа/поражение срабатывает корректно и показывает итог.
6. Выжившие переносятся в следующую миссию.
7. Сохранение после победы сохраняется, после перезапуска игры прогресс на месте.

### 18.3. Критерии приёмки кампании (v1)

- Все 8 миссий проходятся от начала до конца без блокеров.
- Прогресс сохраняется и восстанавливается после перезапуска Unity.
- Среднее время миссии: 10–25 минут; не ниже 80% кадров по 60 FPS на тестовой
  машине.
- Нет ошибок в консоли при обычном прохождении.

## 20. Риски

| Риск | Вероятность | Меры |
|---|---|---|
| NavMesh не тянет 300 юнитов на 3 км | Средняя | Ограничение числа агентов; при необходимости собственный pathfinding по сетке (отдельная веха) |
| Баланс сильно зависит от playtest | Высокая | Все числа вынесены в данные; в C5 отдельный проход |
| Большой объём UI на IMGUI | Средняя | Переход на UI Toolkit в C10 |
| Сохранения ломаются при смене структуры | Средняя | Версия в `campaign.json`, миграция в `CampaignManager.Load` |
| Юнит-модели-заглушки выглядят слабо | Высокая | Принято для прототипа, реальные модели — C10 |

## 22. Глоссарий

- **CP (command points):** очки командования, валюта подкреплений.
- **Сектор:** контрольная зона с доходом CP.
- **Подкрепления:** покупка юнита за CP, появление в тыловой зоне.
- **Выжившие:** юниты игрока, пережившие миссию-победу, переходящие дальше.
- **Опыт (ветеранство):** уровень 0–2, повышает точность.
- **Пробитие / броня:** бронебойная способность против сопротивления брони.
- **Непрямой огонь:** стрельба по цели без своей линии видимости.
- **Lockstep:** синхронная симуляция для сетевой игры (мультиплеер, отложен).
